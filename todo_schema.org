#+TITLE: TODO Schema (Org)

The task format and the task protocol of this vault. It is org mode, unmodified. The protocol used to live in ~task.md~, which is deleted.

Nothing in this schema is invented. Every rule is either org's own behaviour or a restriction on it. Where a rule restricts org, the reason is measured, not taste.

* Inspiration

[[https://orgmode.org/][org-mode]] for everything: the heading, the state, the tag, the priority, the planning line, the archive. [[https://github.com/todotxt/todo.txt][todo.txt format]] for the fields: created, completed, due, recurring.

The line schema needs a 400-character regex because the title and the metadata share one flat line. Org gives every field its own slot, so there is nothing left to parse apart.

* Scope

- Org is for tasks and raw capture. Durable prose stays markdown. A repository holds both, and they do not mix.
- ~todo.org~ and ~inbox.org~ live at the repository root, and nowhere else.
- Every other ~.org~ file, anywhere in the repository, is a task source.
- The scanner reads ~*.org~ **and** ~*.org_archive~. It must, because org's archive files end in ~_archive~, not ~.org~.

** Files

| File                  | Location         | Purpose        |
|-----------------------+------------------+----------------|
| ~todo.org~            | repository root  | Active board   |
| ~inbox.org~           | repository root  | Think tank     |
| ~<file>.org_archive~  | beside its source | Archived items |
| ~tmp/~                | repository root  | Scratch for active tasks. Gitignored. |

~archive.org~ does not exist. Archiving uses org's default location: ~<file>.org_archive~, beside the file it came from. A board in ~docs/notes.org~ archives to ~docs/notes.org_archive~.

** Inbox

~inbox.org~ is the think tank: a place for the human to write and read raw thoughts fast. It is plain org - no properties, no metadata, no states.

- ~#+TITLE: INBOX~, and no ~#+TODO:~. The file holds no tasks.
- One thought is one ~*~ heading at column 0, with a non-empty title.
- No ~:PROPERTIES:~ drawer, no ~:ID:~, no ~:CREATED:~, no ~DEADLINE:~, no priority, no tags.
- Never archived. Triage moves a heading out or deletes it.
- The human writes it first. The active agent may append.
- The reader reads ~inbox.org~ like any other task source, so its rules apply. ~* TODO: fix the leak~ is an error - the prompt to promote the thought or reword it. With no ~#+TODO:~, the reader falls back to ~TODO~ and ~DONE~, so ~* TODO fix the leak~ reads as a task; that is the same prompt.

* Format

  #+BEGIN_EXAMPLE
  #+TITLE: TODO
  #+TODO: TODO IN_PROGRESS OPTIONAL LATER | DONE OBSOLETE
  #+STARTUP: logdone

  * Tasks
  ** TODO File quarterly GST return :finance:
     DEADLINE: <2026-07-20 Mon>
     :PROPERTIES:
     :ID: 7f3c1e2a-4b21-4d9e-9a1f-2c8e5d0b7a44
     :CREATED: 2026-07-01
     :END:
     Collect purchase invoices from the shared drive first.

  ** DONE Pay rent :finance:
     CLOSED: [2026-08-05 Wed]
  #+END_EXAMPLE

* Heading

- A task is a line starting with ~*~ at **column 0**, then a space, then a state, then a space, then the title.
- More stars mean deeper grouping: ~*~, ~**~, ~***~. Depth carries no task meaning; see [[*Containers][Containers]].
- The state is one of the six keywords declared in ~#+TODO:~. See [[*States][States]].
- The title is free text. It may contain anything: links, URLs, colons, parentheses, a tilde, an at-sign.
- The title must be non-empty. A bare ~* TODO~ is a task with no title, and a reader rejects it.
- Priority, then tags, follow the title. Both are optional and both are org syntax. See [[*Priority][Priority]] and [[*Tags][Tags]].
- Everything is case-sensitive. ~* todo x~ is not a task. See [[*Conformance][Conformance]].
- Change state by editing the keyword in place. Drop a task by deleting the subtree (git keeps history).

A file title is ~#+TITLE:~, never a ~*~ heading. A heading of ~* TODO~ is a task with an empty title, not a title.

** Containers

- A heading with a state keyword is a task.
- A heading without one is a container. It groups tasks and carries no task data.
- Containers may sit at any depth, and any number of tasks may sit under one.
- **A task may not contain a task.** A nested heading with a state keyword is an error. Parts of a big job are peer tasks joined by a shared tag.

  #+BEGIN_EXAMPLE
  * Tasks
  ** TODO Ship the parser :parser:
  ** DONE Write the reader :parser:
  ** TODO Write tests :parser:

  * Routine
  ** Morning
  - [ ] Dream journal
  - [ ] Hot water with apple cider vinegar
  #+END_EXAMPLE

- A container heading may not start with ~TODO:~. A heading of ~* TODO: To read~ reads like a state but is not one, since the colon follows the keyword. A reader rejects it.

** Tags

- Tags are org tags: at the end of the heading line, colon-delimited, one colon between them: ~:finance:home:~
- The charset is org's own, ~org-tag-re~ = ~[[:alnum:]_@#%]+~. **A hyphen is not a tag character.** ~:raveenkumar-xyz:~ is headline text, not a tag.
- There is one kind of tag. The line schema's ~+project~ and ~@context~ split is gone: ~+finance~ becomes ~:finance:~, ~@home~ becomes ~:home:~.
- Tags are lowercase. Org tags are case-sensitive, so ~:AI:~ and ~:ai:~ would otherwise be two tags that mean the same thing. A writer folds to lowercase; a reader rejects an uppercase tag.
- Tags inherit from a parent container, and ~#+FILETAGS:~ may tag a whole file. Both are allowed and neither is required.

** Priority

- Org's priority cookie, between the state and the title: ~* TODO [#A] Pay rent :finance:~
- Only ~[#A]~, ~[#B]~ and ~[#C]~. Org parses ~[#Z]~ without complaint, so a reader range-checks.
- Optional. Org's ~org-priority-default~ is B, but a writer never emits a priority that was not written.

** Planning line

- Org's planning line, on the line directly after the heading.
- ~due:~ is ~DEADLINE:~. There is no ~SCHEDULED:~ in this schema.
- ~completed:~ is ~CLOSED:~. A time is allowed; org writes one when ~org-log-done~ is on.
- Canonical order when both appear: ~DEADLINE:~ then ~CLOSED:~.

  #+BEGIN_EXAMPLE
  ** DONE Renew Honda Dio insurance :bike:
     DEADLINE: <2026-09-01 Tue>
     CLOSED: [2026-09-01 Tue 18:00]
  #+END_EXAMPLE

** Properties

Org's ~:PROPERTIES:~ drawer. Org writes it directly after the planning line, or directly after the heading when there is no planning line. Measured: both ~org-entry-put~ and ~org-archive-subtree~ place it there, and org's parser reads the properties either way.

| Property          | Written by | Contents                                        |
|-------------------+------------+-------------------------------------------------|
| ~:ID:~            | org-id     | A UUID. The task identity.                      |
| ~:CREATED:~       | a tool     | ~YYYY-MM-DD~. When the task was captured.       |
| ~:ARCHIVE_*:~     | org        | Provenance, written on archiving. See [[*Archiving][Archiving]]. |

- ~:ID:~ is generated by ~org-id-get-create~ and is never reused. It replaces the line schema's ~[T<n>]~.
- ~:CREATED:~ is a convention, not an org built-in. Org has no creation property. It is valid org, org never fills it, and org never removes it.
- Other properties are allowed and ignored: ~:CATEGORY:~, ~:Effort:~, and anything you add. A reader warns, but does not fail, on a property name one edit away from ~:CREATED:~ or ~:ID:~.
- Property names are case-insensitive in org: ~:created:~ and ~:CREATED:~ are the same property. Writers emit uppercase.
- Org pads property values to align them, because ~org-property-format~ is ~"%-10s %s"~. Both ~:ID: abc~ and ~:ID:       abc~ are valid; a reader trims surrounding whitespace.

** Notes

The subtree body, verbatim. Org's own mechanism, and it is the whole reason org wins here.

- Any text between the heading and the next heading is the note.
- A bullet list in the body is a checklist, not tasks.
- There is no ~(note "...")~ form and no single-line constraint. A note may run for pages.
- Markdown and org markup inside a note stay literal to the scanner and render normally in Emacs.

** Checklists

~- [ ]~ and ~- [x]~ are checklists: steps in a procedure, audit or test run that you tick each time. They are not tasks.

- Native org, including the ~[/]~ and ~[1/3]~ cookies.
- A task line always starts with ~*~ at column 0, so a checklist never collides with a task.

** Examples

A task that appears in documentation as an example must not become work. Org gives one mechanism for this, and it is not a code fence.

- **An example task is indented by at least one space.** A ~*~ that is not at column 0 is not a heading. Org agrees: ~org-map-entries~ and the agenda both ignore it.
- Wrap the example in ~#+BEGIN_EXAMPLE~ and ~#+END_EXAMPLE~ so it renders as an example. The block is for the reader. **The indentation is what does the work.**
- A code fence does **not** hide a task. A ~*~ at column 0 terminates the block, so ~#+BEGIN_SRC~ with a column-0 ~* TODO~ inside produces a real task. Measured on org 9.7.11.

  #+BEGIN_EXAMPLE
  #+BEGIN_SRC org
  * TODO this is a real task, not an example
  #+END_SRC
  #+END_EXAMPLE

** Why not a ~COMMENT~ subtree

Org's other candidate is ~* COMMENT Examples~. Measured on org 9.7.11, against indentation:

| Property                                   | Indented example | ~COMMENT~ subtree |
|--------------------------------------------+------------------+-------------------|
| ~org-lint~ issues                          | 7 (low severity) | 0                 |
| ~org-agenda~ skips it                      | yes              | yes, ~org-agenda-skip-comment-trees~ is ~t~ |
| ~org-map-entries~ skips it                 | yes              | no                |
| ~rg '^\*+ TODO'~ skips it                   | yes              | no                |

Indentation wins on the last two rows. A ~COMMENT~ subtree holds real, column-0 headings, so every grep and every reader that does not implement the skip returns examples as tasks. Indentation needs no cooperation at all: a ~*~ that is not at column 0 is not a heading, which is org's own rule.

The cost is one ~org-lint~ warning per example, ~Possibly misplaced heading line~, at low severity. That warning is correct here - the line does look like a heading and is not one. A task file with examples in it will report the same warning, by design.

* Metadata mapping

| Line schema               | Org                                              |
|---------------------------+--------------------------------------------------|
| ~[T<n>]~                  | ~:ID:~ property, a UUID                          |
| ~+finance~                | ~:finance:~                                      |
| ~@home~                   | ~:home:~                                         |
| ~(A)~                     | ~[#A]~                                           |
| ~created:2026-07-01~      | ~:CREATED: 2026-07-01~ property                  |
| ~due:2026-08-19T09:00~    | ~DEADLINE: <2026-08-19 Wed 09:00>~               |
| ~completed:2026-06-28~    | ~CLOSED: [2026-06-28 Sun]~                       |
| ~recurring:monthly~       | ~+1m~ in the ~DEADLINE:~ repeater                |
| ~recurring:2w~            | ~+2w~                                            |
| ~recurring from-done 3w~  | ~.+3w~                                           |
| sub-bullet note           | subtree body                                     |

* Dates and times

Org's timestamp shape. Org accepts a bare date and a date with a time, with or without a day name.

- Date ~<2026-08-19>~, date-time ~<2026-08-19 09:00>~, or org's own ~<2026-08-19 Wed 09:00>~.
- 24-hour clock, no seconds, no time zone.
- One timestamp, no spaces inside the date part. ~<2026-08-19 09:00>~ is one timestamp; ~<2026-08-19 09:00~ is unbalanced and an error.
- Org does not validate the day name. A reader therefore rejects a mismatching day name when one is present - wrong data is an error, not a warning. The example below shows a stored-but-wrong day name.
- ~CLOSED:~ may carry a time. Org writes one when ~org-log-done~ is on, and a time is real information, so the schema allows it.
- ~:CREATED:~ is a date, never a date-time. It is written by a tool, and a tool writes ~YYYY-MM-DD~.

A reader warns on any timestamp that does not match:

  #+BEGIN_EXAMPLE
  <2026-08-19 Xyz>  - day name says Xyz, date is Wednesday; a reader rejects this
  DATE = \d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])
  TIME = ([01]\d|2[0-3]):[0-5]\d
  #+END_EXAMPLE

The pattern checks shape and ranges only. It accepts impossible dates such as ~2026-02-30~; a date parser rejects those.

* Recurring

Org's repeaters, inside the ~DEADLINE:~ timestamp. The line schema's ~from-done~ flag is org's dot prefix, so nothing is invented.

| Schema                | Org          | Counts from     |
|-----------------------+--------------+-----------------|
| ~recurring:daily~     | ~+1d~        | the deadline    |
| ~recurring:weekly~    | ~+1w~        | the deadline    |
| ~recurring:monthly~   | ~+1m~        | the deadline    |
| ~recurring:yearly~    | ~+1y~        | the deadline    |
| ~recurring:2w~        | ~+2w~        | the deadline    |
| ~recurring from-done 3w~ | ~.+3w~    | the completion  |

On completing a recurring task, advance the deadline to the next occurrence instead of leaving it done.

The new deadline is computed from the old deadline, not from the day you finished. Rent stays on the 5th even when paid on the 9th. Use ~.+~ when the item should space itself from the actual completion: a gym visit, a haircut.

* Reference grammar

  #+BEGIN_EXAMPLE
  task      = "*" space state space [ pri space ] title [ space tags ] newline
  container = "*" { "*" } space title [ space tags ] newline
  nested    = "*" { "*" } space state space ...        (* an error *)
  state     = "TODO" | "IN_PROGRESS" | "OPTIONAL" | "LATER" | "DONE" | "OBSOLETE"
  pri       = "[#" ( "A" | "B" | "C" ) "]"
  title     = char { char - newline }                      (* non-empty *)
  tags      = ":" tag { ":" tag } ":"                   (* end of line *)
  tag       = { alnum | "_" | "@" | "#" | "%" }
  space     = " " { " " }
  #+END_EXAMPLE

The ~*~ must be at column 0. ~letter~, ~digit~, ~char~, ~YYYY~, ~MM~, ~DD~, ~hh~ and ~mm~ are the obvious terminals.

The reader is org's own outline scan: a ~*~ at column 0 opens a heading, and everything until the next such line belongs to it. No lookahead, no backtracking, and a report of the column where a line breaks instead of just failing to match.

* Conformance

** Reader

- Reads ~*.org~ and ~*.org_archive~.
- A heading is a ~*~ at column 0. An indented ~*~ is not a heading, in a block or out of it.
- Skips lines between ~#+BEGIN_<name>~ and ~#+END_<name>~, for every block name.
- Reads the states from the file's own ~#+TODO:~ line. A task file that holds tasks must declare one; a reader that finds none treats ~TODO~ and ~DONE~ as the only states.
- Rejects a heading whose state keyword is not declared.
- Rejects a task with an empty title.
- Rejects a task nested inside a task.
- Rejects a tag containing an uppercase letter. ~:AI:~ is an error, not a second tag.
- Rejects a container heading that starts with ~TODO:~.
- Rejects an indented ~*~ followed by a state keyword outside a block: it is a task that would silently vanish.
- **Rejects a near-miss state.** A heading whose first word, ignoring a trailing colon, matches a declared state case-insensitively but not exactly is an error: ~* done x~, ~* Todo x~, ~* in_progress x~. A heading whose first word is one edit away from a declared state of six or more characters is an error: ~* OBOSLETE x~. Shorter states are exempt, so ~* None of the above~ and ~* Water the plants~ stay containers.
- Rejects an unknown key in a ~:PROPERTIES:~ drawer only when the key is unknown to org *and* is a near-miss of a schema property.
- Rejects a timestamp whose day name contradicts its date; see [[*Dates and times][Dates and times]].
- Warns on a ~CLOSED:~ or ~DEADLINE:~ timestamp that does not match the date pattern.
- Accepts any UTF-8 in a title or a note.
- Reports every rejection as ~path:line:col~ and exits non-zero.

** Writer

- Emits ~#+TODO: TODO IN_PROGRESS OPTIONAL LATER | DONE OBSOLETE~ in every file it creates that holds a task.
- Emits ~#+STARTUP: logdone~ so org records ~CLOSED:~ on completion without global configuration.
- Emits ~*~ at column 0, one space between tokens.
- Emits properties in this order, skipping absent ones: ~:ID: :CREATED:~.
- Emits ~:ID:~ before ~:CREATED:~, and the drawer after the planning line.
- Leaves every line it did not change byte-identical.
- Never emits ~SCHEDULED:~, ~:TASK_ID:~, ~:COMPLETED:~, ~:ARCHIVE:~, or a tag containing a hyphen or an uppercase letter.

* Required configuration

Reading needs nothing. A task file describes itself: the states, the tasks, the metadata. Writing needs three global settings, plus one per-file keyword, because org's writer defaults differ from this schema.

  #+BEGIN_SRC elisp
  (setq org-tags-column 0)                                  ; tags one space after the title
  (setq org-archive-save-context-info                       ; no absolute path in the drawer
        '(time olpath category todo itags))
  (setq org-archive-file-header-format "\nArchived entries\n\n")  ; no absolute path in the header
  #+END_SRC

- ~org-tags-column~ is ~-77~ by default and ~org-auto-align-tags~ is ~t~, so org re-pads every heading on save and a one-word title change rewrites the whole line. ~0~ places tags directly after the title with one space.
- The other two stop org writing ~/Users/<name>/...~ into every archive file. ~org-archive-save-context-info~ keeps ~time~, ~olpath~, ~category~ and ~itags~ and drops ~file~.
- Completion logging is set per file with ~#+STARTUP: logdone~, not here, so it travels with the file.

* Archiving

Org's default, unmodified.

- ~org-archive-subtree~ moves a subtree to ~<file>.org_archive~, beside the source file.
- The archive gains ~#    -*- mode: org -*-~ as its first line. That line is required: ~.org_archive~ is not in ~auto-mode-alist~, so without it Emacs does not open the file as org.
- Measured 2026-09-29: ~org archive~ (org CLI 2.0.0) creates the archive without that mode line. Add it once, by hand, after the first archive from a file.
- Org writes no ~#+TODO:~ into a new archive. Add one once; org appends below it and never removes it.
- The default ~org-archive-subtree~ adds **no** ~:ARCHIVE:~ tag. The tag belongs to ~org-archive-to-archive-sibling~, which this schema does not use.
- An archived subtree gains a ~:PROPERTIES:~ drawer: ~:ARCHIVE_TIME:~, ~:ARCHIVE_CATEGORY:~, ~:ARCHIVE_TODO:~, and ~:ARCHIVE_FILE:~ unless the configuration above removes it.
- State changes in place. Archiving is optional housekeeping, not part of completing a task. A ~DONE~ task may sit in ~todo.org~ for as long as you like.

* States

| State         | Meaning                                            |
|---------------+----------------------------------------------------|
| ~TODO~        | Not started                                        |
| ~IN_PROGRESS~ | Actively being worked                              |
| ~OPTIONAL~    | Nice to have - do it if time permits               |
| ~LATER~       | Deferred - worth doing, but not now                |
| ~DONE~        | Completed                                          |
| ~OBSOLETE~    | No longer relevant - kept for the record           |

Life cycle: ~TODO~ -> ~IN_PROGRESS~ -> ~DONE~. ~OPTIONAL~ and ~LATER~ items can be promoted to ~TODO~ or ~IN_PROGRESS~, or dropped (delete the subtree). Any item can become ~OBSOLETE~ instead of being deleted, to keep the record.

A task's kind is a tag, not a state: ~:bug:~ when something behaves wrongly, ~:fixme:~ when it works but needs rework. The state tracks progress and the tag records the kind, so a fixed bug stays findable as a ~DONE~ task with ~:bug:~.

* Protocol

Plain-text kanban. Agents work the board through the [[https://github.com/DCPRevere/org-cli][org CLI]] - measured on ~org~ 2.0.0, 2026-09-29. The file is the bus: agents do not message each other, and a parent agent does not spawn a subagent to coordinate. "The active agent" means whichever agent is running. The format is this file; this section is the operating rule, and it adds no states, tags, or second board.

** Verbs

| Verb    | Command                                                                          |
|---------+----------------------------------------------------------------------------------|
| Create  | ~org -d <dir> add <file> "<title>" --todo <state> --under <container> [--deadline D] [--tag t]~, then ~org -d <dir> property set <file> "<title>" CREATED <today>~ |
| Read    | ~org -d <dir> -f json todo list~, ~org read <file> <ref>~, ~org task show id:<uuid>~ |
| Update  | ~org todo set~, ~org deadline~, ~org priority~, ~org tag add/remove~, ~org property set/remove~, ~org append~ |
| Archive | ~org archive <file> <ref>~ moves the subtree to ~<file>.org_archive~               |
| Delete  | No verb. The human deletes the subtree by hand; ~OBSOLETE~ keeps the record.       |

- Create writes the state word from the file's own ~#+TODO:~ set, never a hardcoded one.
- ~org~ writes ~:ID:~ itself and pads properties to column 0. Measured: the linter accepts that even when the rest of the file is indented by hand.
- Never run ~org task create~ on a board. Measured 2026-09-29: it writes ~tasks.org~, ignores an existing ~todo.org~, and rejects ~--input {"file":"todo.org"}~.
- ~org add~ never writes ~:CREATED:~, with or without ~--under~, and it never creates a file or a container. Without ~--under~ it also inserts at the root. The two-command recipe above is the create path.
- A repository may ship a board linter; run it after a write when one exists.

** Agent writer

1. Set ~ORG_ACTOR~ to a stable name for this process. If it is unset, ask. Do not invent an actor.
2. Pass ~-d <repo-root>~ and ~-f json~ on every call.
3. Pass ~--expected-revision~ on every write, using the revision from the read just done. On ~conflict~, read again and retry once. Never retry with the old hash. Measured 2026-09-29: the ~task~ verbs enforce it; ~todo set~, ~deadline~, ~priority~, ~tag~ and ~property~ accept a wrong hash, so read immediately before a plain edit.
4. Keep the claim UUID in this process. Do not put it in a message to another agent.
5. ~org~ is the only writer of task entries. Do not edit ~*.org~ task files by hand.

Do not pass ~--scheduled~, and do not run ~org schedule~; this schema has no ~SCHEDULED:~. Do not freehand stars, drawers, keywords, or logbook lines. Do not commit ~.org-index.db~, ~.org-tasks.lock~, or ~*.org-lock~.

** Coordination loop

The lock is ~org task claim~, not the keyword. Measured: a claim leaves the keyword at ~TODO~ and records the lock in ~:TASK_CLAIM_ID:~ and ~:TASK_CLAIM_OWNER:~. A human may still set ~IN_PROGRESS~ by hand; that keyword is a status, not a lock.

1. ~org task ready -d <repo-root> -f json~ lists the candidates.
2. Pick by [[*Picking which task][Picking which task]], then ~org task show id:<uuid> -d <repo-root> -f json~ and read the acceptance text in the subtree body.
3. ~org task claim id:<uuid> -d <repo-root> --actor "$ORG_ACTOR" --claim-id <fresh-uuid> --expected-revision <hash>~
4. Do the work. Renew before the lease ends - 30 minutes by default.
5. If it cannot continue, release with a handoff. Do not submit, and do not message another agent.
6. ~org task submit id:<uuid> -d <repo-root> --actor "$ORG_ACTOR" --claim-id <uuid> --expected-revision <hash> --evidence "<what changed>"~
7. A different actor reviews: ~org task approve id:<uuid> -d <repo-root> --actor <other> --expected-revision <hash> --evidence "<review>"~. Same-actor approve is rejected, and a review decision needs evidence. Approve writes ~DONE~ and ~CLOSED:~ when the file declares ~#+STARTUP: logdone~.

After a claim the task leaves ~org task ready~ (its status becomes ~working~); read it with ~org task show~.

** Picking which task

Priority first: ~[#A]~, then ~[#B]~, then ~[#C]~, then unprioritised. Within one priority, take the oldest ~:CREATED:~ date; a task without ~:CREATED:~ sorts last.

** Completing a task

1. Verify against the acceptance criteria in the subtree body.
2. Agents submit, then a different actor approves; see [[*Coordination loop][Coordination loop]].
3. A human may change the keyword to ~DONE~ in place. Org records ~CLOSED:~ itself, because the file declares ~#+STARTUP: logdone~.
4. Leave it where it is. Archiving is optional housekeeping; see [[*Archiving][Archiving]].

** Dropping a task

1. Delete the subtree. Git keeps history. Agents leave deletion to the human - the verb table has no delete.
2. Use ~OBSOLETE~ instead when the record is worth keeping.

** When to create a task

- Multi-step work that benefits from persistence.
- When the human asks to track something.
- Not for single-command trivialities.

** Capture

Write to ~inbox.org~ when the human says "remember", "remind me", "note this", "save it for later", or "create a task" and the work is not yet shaped. See [[*Inbox][Inbox]] for the file shape.

- One thought per ~*~ heading. Plain title, nothing else.
- Do not add a state, an id, a deadline, a priority, or a tag.
- ~inbox.org~ is the human's think tank first. Append; never reformat it.

Do not capture:

- Well-defined work with clear acceptance criteria. Write it to ~todo.org~ as a task; see [[*When to create a task][When to create a task]].
- Durable knowledge. Write it to ~docs/~.
- A single-command triviality. Just do it.

** Triage

The human reviews ~inbox.org~. For each heading, exactly one of:

| Decision          | Action                                                |
|-------------------+-------------------------------------------------------|
| Make it a task    | Move the heading to ~todo.org~, add a state and ~:ID:~ |
| Durable knowledge | Move it to ~docs/~                                    |
| Drop it           | Delete the heading                                    |

After triage the heading is gone from ~inbox.org~. It is temporary, not a ledger; git keeps the history.

** Temporary vs durable data

| What                                   | Where         | Git     |
|----------------------------------------+---------------+---------|
| Scratch notes, logs, debug output      | ~tmp/~        | ignored |
| Detailed specs, architecture notes     | ~docs/~       | tracked |
| Task state, identity, priority, dates  | the task file | tracked |

** Session start

At session start, the active agent reads:

- The repository's ~todo.org~ - the current board.
- The repository's ~inbox.org~ - untriaged capture.
- The ~todo.org_archive~ beside it, when checking whether work was already done.

* Migration

Done, 2026-09-25.

1. ~~Reader~~: ~~,todo.py~~ scans ~*.org~ and ~*.org_archive~, reads each file's ~#+TODO:~, splits the heading, and reports ~path:line:col~. The near-miss state check and the day-name check are the only parts that are not org's own scan. (dot commit ~61370526~.)
2. ~~Writer~~: the ~migrate-todo~ skill's converter emits org, keeping every untouched line verbatim.
3. ~~Converter~~: 9,795 items migrated into repo-root ~todo.org~ / ~*_archive~ files across 19 repositories, one commit per repo. Fifteen files were not boards - test fixtures, format documents, skill files and a blog post - and did not convert: indented lines and code fences are examples, not work.
4. ~~Archives~~: ~<file>.org_archive~ beside the board, with the mode line and a ~#+TODO:~ line.
5. ~~Snapshot script~~: ~Main_Quest/scripts/snapshot.py~ reads org beside the line schema. (Main_Quest commit ~67fdbcb~.)

Every item has moved and both readers read org. ~todo_schema.md~ and ~todo_schema_lisp.md~ are deleted; this document stands alone.

What remains is per-repository adapter work, tracked in each repository: Main_Quest's ~mq-core~ still parses the line regex, the vim plugin still edits the line format, and three repositories that hold no tasks have not yet been given their empty file sets.

* Decisions

| Date       | Decision                                                    | Why                                                              |
|------------+-------------------------------------------------------------+------------------------------------------------------------------|
| 2026-09-24 | Org is the store, markdown is legacy                        | One destination. The lisp schema was never adopted: zero real items in the vault |
| 2026-09-24 | Org is for tasks and raw capture, durable prose stays markdown | Markdown renders everywhere; org renders in Emacs                 |
| 2026-09-24 | ~todo.org~ and ~inbox.org~ at repository root only          | One board per repository, one place to look                       |
| 2026-09-24 | ~inbox.org~ is a plain think tank, no metadata              | Human writes and reads it fast; the board carries the structure    |
| 2026-09-24 | ~inbox.org~ and ~todo.org~ stay separate, read strictly     | Different trust and lifecycle; a state-like word is the prompt     |
| 2026-09-24 | Any other ~.org~ file anywhere is a task source             | Tasks stay where the work is                                      |
| 2026-09-24 | The lisp schema dies                                        | Zero users, and it would need its own converter for nothing        |
| 2026-09-24 | Source files carry no task format                           | Measured: every code-embedded task in the vault is a test fixture  |
| 2026-09-24 | Flat tags, no ~+~ and no ~@~, no project/context split      | The corpus has no hyphens or underscores in a tag; ~+~ is not in ~org-tag-re~ |
| 2026-09-24 | Every ~.org~ file is a task source; a task file declares ~#+TODO:~ | A file that is never opened loses its tasks silently               |
| 2026-09-24 | Grouping only, a task may not contain a task                | Measured: 0 nested tasks. Containers already group the corpus      |
| 2026-09-24 | Task identity is ~:ID:~, a UUID                             | Org-native, and measured: ~[T<n>]~ appears once in 9,956 items     |
| 2026-09-24 | ~completed~ is ~CLOSED:~, time allowed                      | The only slot org, the agenda and ~org-lint~ all understand        |
| 2026-09-24 | ~created~ is the ~:CREATED:~ property                       | Valid org, one line, maps 1:1 to 9,645 existing values             |
| 2026-09-24 | State changes in place, archiving is optional               | Org's model. Removes the state-to-file split, which already leaks  |
| 2026-09-24 | Archiving uses org's default location                       | ~<file>.org_archive~ beside the source, no ~#+ARCHIVE:~ needed     |
| 2026-09-24 | The two path lines are removed by configuration             | Otherwise ~/Users/<name>/...~ is committed into every archive      |
| 2026-09-24 | A near-miss state keyword is an error                       | ~* done x~ otherwise becomes a container and vanishes silently     |
| 2026-09-24 | An example task is indented                                 | Measured: a column-0 ~*~ ends a block, so a code fence hides nothing. A ~COMMENT~ subtree passes ~org-lint~ but leaves examples visible to ~rg~ and to ~org-map-entries~ |
| 2026-09-24 | Tags are lowercase, and a reader rejects an uppercase tag | Org tags are case-sensitive, so ~:AI:~ and ~:ai:~ would be two tags meaning one thing. The corpus holds four uppercase occurrences |
| 2026-09-24 | ~org-tags-column~ is 0                                      | ~org-auto-align-tags~ is ~t~, so a title edit otherwise rewrites the line |
| 2026-09-26 | Agents claim through ~org~, not by editing the keyword     | Measured on ~org~ 2.0.0: claim keeps ~TODO~, approve writes ~DONE~. Freehand edits race. ~org task create~ writes ~tasks.org~, so it is not the board writer |
| 2026-09-29 | The agent protocol lives here, in one file                 | Two files drifted: ~orchestration.md~ was never merged, and both links to it dangle. The verbs, the writer rules and the loop are todo work, so they belong with the format |
