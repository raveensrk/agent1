The investigator judges each task once its report is written, and a trivial task skips every later ant.
- Trivial means all of: small, known scope (1-2 files, easy to find); one sensible way to do it, no design choice; one task that cannot be split. Docs or config only is a plus, not a must. A task that needed any question to the user is never trivial.
- The live investigator replies with trivial and trivialWhy. In the fallback, ishikari-plan.js returns stage 'trivial' with why, report, testCommand and checkCommand before the requirement and architect ants run.
- The skill asks the user once to confirm the fast path. No runs the full plan with investigated set.
- On the fast path the main session edits on branch ishikari/<run>/fast in a worktree under the state folder, runs testCommand then checkCommand there, and fast-forwards main only when both pass. It adds and marks the requirement and logs one "fast path landed" entry, all through ishikari.py.
- Escalation: more than 2 files, a design choice, more than one task, or a failing test or check a small fix does not clear. The edits are thrown away and ishikari-plan.js runs with investigated and escalated: the add requirement and architect ants read why, and a "fast path escalated" entry is logged. The run then carries on without asking.
